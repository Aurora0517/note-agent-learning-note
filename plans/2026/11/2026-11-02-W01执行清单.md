## 必踩的坑（提前避）

1. **key 硬编码进代码** → 一定走 `.env`，且确认 `git status` 里没有它
2. **直连 OpenAI 超时** → 换国内兼容端点，不是你的代码问题
3. **流式输出不 flush 看着像卡住** → 逐 chunk 打印并 flush
4. **`.env` 误提交** → 提交前 `git status` 扫一眼；本仓库已配 `.gitignore`
5. **uv 和系统 python 混用** → 全部用 `uv run`，别 `python main.py`
6. **`~/.local` 归 root，装不上 uv** → 报错是 `mkdir: ~/.local/bin: Permission denied` 时，先 `ls -ld ~/.local` 看所有者；不是你自己的就跑 `sudo chown -R $(whoami):staff ~/.local`。注意这只修 `~/.local`，不影响系统目录
7. **装 uv 时 GitHub 下载被 reset** → 报 `curl: (56) Recv failure`，安装器会自动换备用源重试，让它跑完再看结果，别提前中断
8. **项目名数字开头 + `uv init` 默认打成 package** → 目录叫 `01-cli-chat` 时，`uv init --app` 默认会生成 `src/01_cli_chat/` 包，而 `01_cli_chat` 不是合法 Python 标识符，`uv run` 构建会报错。用 `uv init --app --no-package` 生成扁平的 `main.py` 布局，正好也符合本清单「一个文件一个入口」的练法
9. **照着老教程抄模型名** → `deepseek-chat` 已是遗留名，现役是 `deepseek-flash` / `deepseek-v4-pro`。同理价格表也常变（`deepseek-flash` 高峰/低峰差一倍，缓存命中/未命中输入价差 50 倍），动手前先看官方定价页 [api-docs.deepseek.com/quick_start/pricing](https://api-docs.deepseek.com/quick_start/pricing)
10. **以为 thinking 默认关闭** → DeepSeek 的思考模式**默认开启**且 effort=high，思维链 token 一起计入 `completion_tokens`。学「请求-响应」链路时用 `extra_body={"thinking": {"type": "disabled"}}` 关掉，否则耗时和费用都不好对标；且思考模式下 `temperature` 等采样参数**设了也不生效**
11. **流式下忘了 `stream_options={"include_usage": True}`** → 最后一个 chunk 不带 usage，token 数和费用统计直接断供，Day 2 建立的成本观测在 Day 3 全废
12. **`print` 不 flush 等于没流式** → 输出攒在缓冲区最后一次性刷出，看着和非流式一样；重定向到管道/文件时必现
13. **流式里直接 `chunk.choices[0]`** → 带 usage 的那个 chunk 的 `choices` 是空列表，会 IndexError，必须先判空
14. **多轮对话把失败的那一问留在历史里** → 请求失败或半途 Ctrl+C 时，`user` 消息已 append 但 `assistant` 回答没写回，历史里会出现连续两条 user，既污染上下文又白占 token。失败分支要 `messages.pop()`
15. **system prompt 里掺时间戳/随机数** → 前缀每轮都不一样，缓存永远命中不了。DeepSeek 缓存按 64 tokens 粒度匹配前缀，命中/未命中输入价差 50 倍，长对话场景这是最大的一笔钱
16. **忘了关 SDK 自带重试** → `OpenAI` 默认 `max_retries=2`，叠加自己写的 3 次重试等于最多 9 个真实请求，日志上看不出来、账单上全在。必须 `max_retries=0`
17. **对 4xx 也重试** → 401/403/404/400 重试一万次结果一样，只白烧配额和时间。只有连接失败/超时/429/5xx 值得重试
18. **流式已经开始吐字了还重试** → 用户会看到同一段内容讲两遍，半句话也撤不回。只重试「建立连接」，中途断流就保留已输出内容并明确告知不完整
19. **退避里先夹上限再加抖动** → `min(cap, delay)*jitter` 会把上限顶破（实测出现 19s > 16s 的 cap）。正确写法是先抖后夹：`min(cap, delay*jitter)`
20. **配置对象用 dataclass 默认 `repr`** → 会把 `api_key` 原样打进日志和异常栈。`Settings` 必须显式覆写 `__repr__` 脱敏，省这一行就是一次密钥泄露
21. **`argparse` 的 `ArgumentDefaultsHelpFormatter` 会误导** → `--no-stream`（`store_false`）的帮助里会显示「default: True」，因为打的是 dest 的默认值而不是「关掉流式」的语义。想显示默认值就在 help 文本里自己写清楚
