## 卡在哪（按耽误的时间排）

1. **`~/.local` 归 root**（约 20 分钟）。2024 年某次 `sudo` 留下的坑，`uv` 安装直接 `Permission denied`。教训：装任何往 `~/.local` 写的工具前，先 `ls -ld ~/.local`。
2. **`deepseek-chat` 已退役**。照文档里的老名字配，核对官方定价页才发现现役是 `deepseek-flash` / `deepseek-v4-pro`。教训：模型名、价格、参数默认值都别信三个月前的教程，动手前看一眼官方定价页。
3. **`uv init` 默认打成 package**。目录名 `01-cli-chat` 数字开头，生成 `src/01_cli_chat/` 包，不是合法 Python 标识符，构建必挂。加 `--no-package` 解决。
4. **GitHub 下载被 reset**。`curl: (56) Recv failure`，安装器自动换备用源才成功。已知问题，不影响结论但拖时间。
5. **openai 3.x 用 `httpx2` 不是 `httpx`**。自检脚本 `import httpx` 直接 ModuleNotFoundError，而教程里全是 `httpx`。

共性：**两个是本机历史遗留，两个是版本演进**。没有一个属于「逻辑想不明白」。这说明阶段 0 的难度不在认知，而在环境细节——也意味着这类问题完全可以靠「先探测再动手」消掉。

## 认知更新：这周真正改变我想法的四件事

**1. 「快」是个可以拆开的指标。**
以前看接口耗时只有一个数。拆成 TTFT 和总耗时之后才发现：出字速度 120+ tok/s 是**人眼阅读速度的十倍以上**，意味着只要第一个字到了，后面的内容永远不会让人等。所以「感知延迟 ≈ TTFT」，这是设计问题不是实现问题。聊天产品全做打字机效果，不是在装可爱。

**2. 无状态这件事比想象中更彻底。**
模型不记得上一句。所谓记忆全是客户端每轮重发历史。推下去就是：n 轮对话的累计输入 ≈ n²/2 × 每轮增量，**轮数翻倍花费四倍**。这解释了为什么真实产品要搞滑动窗口、摘要压缩——不是省小钱，是省平方级的钱。

**3. 缓存是长对话唯一的大杠杆，但它有脾气。**
命中/未命中的输入单价差 50 倍。但缓存按 64 tokens 粒度做**前缀匹配**，几十 token 的短前缀根本不命中，而且前缀必须**完全一致**。所以「system prompt 放最前 + 内容固定」不是风格偏好，是省钱的设计约束；往里掺时间戳、用户名就等于主动放弃缓存。

**4. 重试写错的代价是乘法。**
SDK 自带 `max_retries=2`，叠加自己写的 3 次，一次调用最坏发 9 个真实请求，日志上看不见、账单上全在。而且 401 这种错重试一万次也一样——**正确的重试是一张判定表，不是一句 try/except**。

## 计划本身要修的地方

复盘的价值一半在改计划。这周暴露出四处：

1. **成本预估偏差过大**：清单写「16 周 100~300 元」，实测单次 ¥0.0001~0.0014。建议改成「调试期总花费 < 5 元，真正的钱花在长上下文、批量评测和刷 benchmark 上」。
2. **装 uv 漏了 PATH 一步**：官方脚本会往 `.zshrc` 追加，但非交互 shell 不读 `.zshrc`，脚本/CI 里会找不到 `uv`。补充说明更好。
3. **模型名和价格没写「什么时候核对的」**：任何写死模型名和价格的文档都会过期。建议清单里直接给官方定价页链接 + 「动手前先核对」的提醒。
4. **Day 2 和 Day 3 有重叠**：Day 2 的非流式调用其实是 Day 3 流式的对照组，分开两天做会重复搭环境。合并成「一次调用 + 两种模式对比」更紧凑，省 1h。

## 下周（阶段 1 第 2 周）：三个我想带着答案回来的问题

预读 Prompt 工程与结构化输出后，列出三个真问题——不是「什么是思维链」这种能搜到定义的，是这周写代码时冒出来、且下周必然要撞上的：

1. **怎么让模型稳定吐 JSON，并且失败时能自愈？**
   现在 `usage`、`choices` 我都是直接取。一旦让模型输出结构化字段，`json.loads` 失败率就是上线风险。想知道：schema 约束该多严？解析失败重试几次就停？重试时把原始错误回灌给模型有用吗？（对照阶段 1 的「结构化输出 8h」）

2. **Function Calling 的工具 schema，参数描述写到什么程度模型才不会乱填？**
   这周 `retry.py` 的判定表是我手写的 if/else，如果换成模型自己决定调哪个工具，它凭什么判断得对？想知道：description 的粒度、枚举值和自由文本的取舍、并行调用时结果顺序怎么保证不错乱。（对照「Function Calling 12h」）

3. **Prompt 改动怎么验证「没变差」？**
   这周所有指标都有数字（TTFT、tokens、费用），唯独 prompt 的效果只能靠眼睛看。想知道：要不要建一个 10~20 条的小样本集做回归？怎么定义「通过」？改 prompt 时怎么避免「改 A 好了一点、B 坏了没人发现」？（对照「Prompt 工程 8h」+「工程化 4h」）
