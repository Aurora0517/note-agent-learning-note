- 创建日期：2026-10-29

- 状态：进行中

## 一、起点盘点

### 可迁移优势

| 优势 | 在 Agent 全栈里的价值 |
| --- | --- |
| 客户端工程能力（生命周期、异步、状态管理、性能） | 做端侧 Agent / 流式交互时，比纯后端更懂体验与资源约束 |
| 多端经验（Android + HarmonyOS + 小程序） | 「端侧 AI 助手」方向人少，是差异化卖点 |
| 用户视角与产品手感 | Agent 产品成败很大程度在交互设计与兜底体验 |
| 已有工程习惯（Git、调试、发布） | 少走野路子，能直接上手工程化 |

| 缺口 | 为什么关键 | 优先级 |

## 三·五、后端知识怎么补（并行轨道）

### 结论先说

**必须补，但只补两档：面试够用、项目够用。不要系统学后端。**

两个方向的极端都要避免：

- 只学 Agent 不碰后端 → 一面考 MySQL 索引、Redis 三个缓存问题、幂等限流，直接卡住。这些恰好是「能不能扛住线上流量」的判据，AI 应用岗一样要考。
- 跑去完整学 Java / Spring 六个月 → 你的栈是 Python + FastAPI，Java 后端对 Agent 岗零加分，还挤掉了做项目的时间。

### 三档清单

| 档位 | 内容 | 处理方式 |
| --- | --- | --- |
| **必须会**<br>（高频且项目真用） | MySQL：B+ 树索引、最左前缀、索引失效场景、事务隔离级别与 MVCC、慢查询定位<br>Redis：缓存穿透/击穿/雪崩、过期与淘汰策略、分布式锁、缓存与数据库一致性<br>网络：HTTP 状态码与幂等语义、TCP 三次握手/四次挥手、HTTPS 握手、DNS<br>并发：进程/线程/协程区别、`async` 的适用与坑、并发控制与背压<br>API：REST 设计、鉴权（JWT/Session）、限流、重试与幂等 | 精读 + 能画图讲清 + 项目里真用过 |
| **知道即可**<br>（能接住一层追问） | 消息队列（Kafka/RabbitMQ）适用场景、至少一次投递与重复消费处理；分库分表思路；CAP 与一致性取舍；GC 是什么（不用会调优） | 记住结论 + 一个具体例子，不深挖 |
| **可以不会**<br>（大方承认） | 分布式事务落地细节、K8s 深度运维、JVM 调优、Java 生态框架 | 直接说「没在生产用过，我的思路是…」，别硬编 |

诚实比硬答得分高。面试官最怕的不是「不会」，而是「什么都敢说」。

### 怎么补（不新开阶段）

- **整块 2h/周（W3–W13）**：只在项目里练。阶段 2 加 MySQL 持久化与索引，阶段 3 加 Redis 缓存与限流，阶段 4 加幂等、事务与监控。**不单独做「后端学习项目」**，那是纯浪费时间。
- **碎片 20min/天**：通勤、排队时刷高频题。按主题过，一周一个主题（索引 → 事务 → 缓存 → 网络 → 并发），过完自己口述一遍录音，回放听哪里卡。
- **不背八股文，背因果**：每个知识点都问自己「不这么做会出什么事」，答得出因果，追问就穿不透。

### 一句话验收标准

能对着白板讲清：**「我这个 RAG 服务，10 万文档、100 QPS，MySQL 和向量库怎么分工、缓存放哪一层、慢了先看哪里」**——这题能答好，后端部分就够用了。

## 六、差异化策略（这是你的护城河）

纯后端转 Agent 的人很多，**懂移动端 + 懂 Agent** 的人很少。建议始终往这条线上靠：

1. 项目选题优先带「端」：App 内 AI 助手、端侧小模型 + 云端 Agent 协同、崩溃/性能分析 Agent
2. 关注 HarmonyOS AI 能力（端侧推理、系统级 AI 接口），这是国内稀缺方向
3. 面试时把「客户端性能约束」翻译成「Agent 的 token / 延迟 / 成本约束」，这是同一套思维

| 时间被工作挤掉 | 优先保阶段 3、4；阶段 0、1 可压缩 |
| 中途怀疑方向 | 第 8 周做一次中期检查，看是否已有可用产出，没有则砍范围而不是延期 |

## 八、求职并行（第 10 周起启动）

- **简历改造**：3 个项目各写一条 STAR，突出「量化效果 + 技术取舍」，弱化「用了什么框架」
- **LLM 面试准备**：RAG 设计题、Agent 系统设计题、工具调用失败兜底、成本与延迟优化
- **后端高频题清单**（按「必须会」档准备，一周一主题）：
  1. 索引：为什么用 B+ 树、什么情况索引失效、联合索引最左前缀
  2. 事务：四个隔离级别各自解决什么问题、MVCC 怎么实现、幻读
  3. 慢查询：怎么定位、`explain` 看哪些列、深分页怎么优化
  4. 缓存：穿透/击穿/雪崩各自的解法、缓存与库不一致怎么处理、过期策略
  5. 锁：分布式锁怎么实现、为什么要 fencing token、Redis 锁的坑
  6. 网络：TCP 三次握手为什么不是两次、HTTPS 握手过程、HTTP/1.1 与 2 的差别
  7. 并发：协程与线程的区别、`async` 里做阻塞操作会怎样
  8. 服务治理：限流算法（令牌桶/漏桶/滑动窗口）、重试的幂等前提、熔断
  9. 消息队列：为什么用、至少一次与重复消费怎么处理
  10. 系统设计：短链服务、秒杀、AI 网关限流——任选一个能画图讲 20 分钟
- **投递节奏**：第 14 周开始小批量投递，用真实面试反馈反过来修计划
- **加分项**：给 LangGraph / MCP 生态提 1~2 个 PR（文档纠错也算），比刷题更能证明动手能力
