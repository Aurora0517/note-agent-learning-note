# Agent 全栈转型学习计划

- 创建日期：2026-10-29
- 目标周期：2026-11-02 ~ 2027-02-21（16 周）
- 状态：进行中
- 投入假设：每周 10~12h（工作日 4×1.5h + 周末 6h）；若实际时间不同，按比例整体拉伸，不要压缩阶段顺序
- 背景：4 年工作经验 / 3 年开发（Android、HarmonyOS、小程序），目标转 Agent 全栈

## 一、起点盘点

### 可迁移优势

| 优势 | 在 Agent 全栈里的价值 |
| --- | --- |
| 客户端工程能力（生命周期、异步、状态管理、性能） | 做端侧 Agent / 流式交互时，比纯后端更懂体验与资源约束 |
| 多端经验（Android + HarmonyOS + 小程序） | 「端侧 AI 助手」方向人少，是差异化卖点 |
| 用户视角与产品手感 | Agent 产品成败很大程度在交互设计与兜底体验 |
| 已有工程习惯（Git、调试、发布） | 少走野路子，能直接上手工程化 |

### 能力缺口（按优先级）

| 缺口 | 为什么关键 | 优先级 |
| --- | --- | --- |
| Python + FastAPI 后端 | Agent 生态的默认语言，绕不开 | 高 |
| LLM 应用工程（Prompt / Function Calling / 结构化输出 / 流式 / 成本） | 地基，后面所有东西都建在这上面 | 高 |
| RAG 全链路（解析→切分→检索→重排→评测） | 企业落地最高频的场景 | 高 |
| Agent 编排（LangGraph / MCP / 记忆 / 多工具） | 「Agent 工程师」岗位的核心考点 | 高 |
| 评测与可观测（Eval / Trace / 成本看板） | 区分「玩过 demo」和「能做产品」的分水岭 | 中 |
| 前端 Web（Next.js） | 全栈的「全」字，且演示效果直接影响面试 | 中 |
| 部署运维（Docker / 云主机 / CI） | 能给出公网可访问链接，说服力翻倍 | 中 |
| 模型训练 / 微调 / RL | 应用岗短期用不上，先跳过 | 低 |

## 三、路线图（5 个阶段）

### 阶段 0：地基（第 1 周｜11-02 ~ 11-08｜约 12h）

| 模块 | 要点 | 投入 |
| --- | --- | --- |
| Python 现代语法 | 类型注解、`async/await`、`pydantic`、异常处理 | 4h |
| 工程环境 | `uv` 建项目、目录结构、`.env` 管理密钥 | 2h |
| 第一次调用 LLM | 官方 SDK 跑通、流式输出、看 token 与费用 | 4h |
| 仓库规范 | 本仓库的提交与推送流程跑一遍 | 2h |

**产出**：`demo/01-cli-chat` —— 命令行流式对话，支持多轮与错误重试。
**验收**：能从零重建环境并在 10 分钟内跑起来。

### 阶段 1：LLM 应用工程（第 2–5 周｜11-09 ~ 12-06｜约 48h）

| 模块 | 要点 | 投入 |
| --- | --- | --- |
| Prompt 工程 | 角色/约束/少样本、思维链、失败重试与自纠 | 8h |
| 结构化输出 | JSON Schema 约束、解析容错、校验失败重试 | 8h |
| Function Calling | 工具 schema 设计、并行调用、结果注入、异常兜底 | 12h |
| 上下文与成本 | 截断策略、摘要压缩、缓存命中、批处理、延迟优化 | 10h |
| 安全 | Prompt 注入、越权工具调用、输出过滤 | 6h |
| 工程化 | 日志、重试、超时、统一 LLM 网关封装 | 4h |

**产出**：`demo/02-doc-qa-cli` —— 带工具调用的文档问答 CLI（能读文件、算数、查网页）。
**验收**：同一个需求，换模型（如 OpenAI ↔ 国产模型）只需改配置，代码不动。

### 阶段 2：RAG 全链路（第 6–9 周｜12-07 ~ 01-03｜约 48h）

| 模块 | 要点 | 投入 |
| --- | --- | --- |
| 文档解析 | PDF / Markdown / 网页，表格与代码块处理 | 8h |
| 切分策略 | 定长 / 语义 / 按标题层级，重叠与元数据 | 8h |
| 向量化与存储 | embedding 选型、pgvector 或 Qdrant、索引参数 | 10h |
| 检索增强 | 混合检索（BM25 + 向量）、rerank、多路召回、查询改写 | 12h |
| 评测 | 召回率、答案忠实度、构造小测试集（RAGAS 思路） | 8h |
| 服务化 | FastAPI 接口、流式返回、最小前端页面 | 2h |

**产出**：`demo/03-knowledge-base` —— 个人知识库服务，支持上传文档、带引用来源回答。
**验收**：给 20 条问题做基准集，改动检索策略后能量化对比效果（不接受「感觉变好了」）。

### 阶段 3：Agent 核心（第 10–13 周｜01-04 ~ 01-31｜约 48h）

| 模块 | 要点 | 投入 |
| --- | --- | --- |
| Agent 范式 | ReAct、Plan-Execute、Reflection，各自适用场景 | 8h |
| 编排框架 | LangGraph（重点学透）、对比 CrewAI / 自研循环 | 16h |
| 工具生态 | MCP 协议、代码执行、HTTP 工具、浏览器自动化 | 10h |
| 记忆与状态 | 短期上下文、长期向量记忆、断点续跑 | 8h |
| 多 Agent | 角色分工、通信协议、成本失控的防法 | 6h |

**产出**：`demo/04-dev-assistant` —— **移动端研发助手 Agent**：输入需求或崩溃日志，自动定位、检索历史 issue、给出修复建议并生成补丁草稿。
> 选题理由：直接用你 3 年 Android/HarmonyOS 经验，工具链和知识库都是你熟的，做出来可信度最高。

**验收**：在 10 条真实崩溃日志上，能给出可用的定位结论，且单次成本可控（< ¥0.5）。

### 阶段 4：全栈交付与包装（第 14–16 周｜02-01 ~ 02-21｜约 36h）

**验收**：陌生人拿到链接 3 分钟内能跑通主流程，README 里有架构图和取舍说明。

## 六、差异化策略（这是你的护城河）

纯后端转 Agent 的人很多，**懂移动端 + 懂 Agent** 的人很少。建议始终往这条线上靠：

1. 项目选题优先带「端」：App 内 AI 助手、端侧小模型 + 云端 Agent 协同、崩溃/性能分析 Agent
2. 关注 HarmonyOS AI 能力（端侧推理、系统级 AI 接口），这是国内稀缺方向
3. 面试时把「客户端性能约束」翻译成「Agent 的 token / 延迟 / 成本约束」，这是同一套思维

## 七、风险与止损

| 风险 | 对策 |
| --- | --- |
| 贪多，什么都学一半 | 每阶段只做一个项目，做完再进下一阶段；不做完不允许开新坑 |
| 只看不写，看了很多视频 | 代码量 > 阅读量，文档当天必须跑通最小例子 |
| 追新框架，反复换技术栈 | LangGraph 学透一个，其余了解即可；换框架不产生经验 |
| 时间被工作挤掉 | 优先保阶段 3、4；阶段 0、1 可压缩到 2 周内速通 |
| 中途怀疑方向 | 第 8 周做一次中期检查，看是否已有可用产出，没有则砍范围而不是延期 |
