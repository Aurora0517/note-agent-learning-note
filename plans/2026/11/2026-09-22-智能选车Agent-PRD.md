## 1. 背景与定位

个人作品集项目，目标是**完整预演车企「销售点单 + 需求评审」业务闭环的微缩版**：

- 对标业务 A：经销商与 AI 多轮对话选型 → 查生产历史 → 已产车型直接报价下单；
- 对标业务 B：未生产车型 → 转需求评审 → 检索历史数据生成初步配置单 → 人工评审定稿。

本项目将两个环节做成了 C 端选车场景的微缩闭环，覆盖：多轮对话编排、工具调用、RAG、MCP 工具层、异步长流程（挂起/恢复）、人工评审（human-in-the-loop）、可观测与评测。

**明确不做**：真实交易与支付、真实供应商数据、完整多租户实现（仅预留设计）、生产级安全加固。

## 2. 用户与角色

| 角色 | 说明 | 使用端 |
|---|---|---|
| C 端用户 | 有购车意向，选车咨询 / 对比 / 看报价 / 下单模拟 | Web 单页聊天（Android 为可选扩展） |
| 管理员 | 对应"研究院评审"角色：评审需求单与配置单、维护知识库、查看评测 | Web 管理端 |

## 3. 核心业务流程

```
用户多轮对话 → 收集槽位（预算/用途/乘坐人数/能源/充电条件/必装配置）
  → 槽位完整 → 查车型库判定：在售 / 停售 / 未覆盖
    ├─ 在售 → 推荐 Top3~5 → 可对比 → 选定 → 报价单（含金融方案）
    │         → 用户确认 → 创建订单（模拟）→ 订单状态
    └─ 停售/未覆盖 → 生成定制需求单（结构化 + 依据引用）→ 进入评审队列
                        → 管理员评审通过 → 触发配置单生成
                        → 基准车型检索 + 差异项替代建议（每项带引用）
                        → 管理员评审配置单 → 定稿 / 驳回
全程可插话：知识库问答（政策 / 口碑 / 参数）
```

关键体验约束：
- 追问一次不超过 2 个问题；槽位确认使用卡片，不打字确认
- 报价金额由规则引擎计算，LLM 只做解释与排版（金额零幻觉红线）
- 定制需求单/配置单的每一行建议必须带来源引用（历史车型/文档），无引用不入单

## 4. 功能需求

| 编号 | 功能 | 描述 | 优先级 | 里程碑 |
|---|---|---|---|---|
| F1 | 多轮选型对话 | 意图识别、槽位抽取、追问澄清（interrupt）、槽位卡片确认 | P0 | M2（M1 先做单轮工具版） |
| F2 | 车型检索与判定 | 结构化筛选 + 语义检索；返回 在售/停售/未覆盖 判定 | P0 | M1（M3 语义增强） |
| F3 | 车型对比 | 2~4 款车参数对比表 | P1 | M2（随推荐报告输出） |
| F4 | 报价与金融方案 | 指导价 + 模拟优惠；首付/月供计算（等额本息，纯规则） | P0 | M1 |
| F5 | 下单模拟 | 确认报价 → 生成订单记录 → 订单状态查看 | P1 | M2 |
| F6 | 定制需求单 | 未覆盖需求 → 结构化需求单（schema 强校验 + 依据） | P0 | M2 |
| F7 | 配置单生成 | 基准车型检索 + 差异项替代建议 + 引用，输出配置单初稿 | P1 | M3 |
| F8 | 评审端 | 需求单/配置单评审（通过/驳回）；M4 主线为极简单页，知识库管理与评测看板为可选扩展 | P1 | M4 |
| F9 | 知识库 RAG 问答 | 政策/口碑/参数三类知识库，带引用回答 | P1 | M3 |
| F10 | 评测与观测 | 评测集、LLM-as-judge、Langfuse 全链路 trace | P0 | M2 起持续 |

### 验收要点

- **F1**：给定期望槽位集合的对话脚本，槽位抽取准确率 ≥ 90%；追问轮次中位数 ≤ 2
- **F2**：在售/停售/未覆盖判定准确率 ≥ 95%（评测集）；结构化筛选响应 < 500ms
- **F4**：金融方案与手工公式计算一致（纯函数断言，零容错）；页面展示 < 200ms
- **F6**：需求单字段完整率 100%（schema 校验强制）；每条需求带 ≥1 条依据引用
- **F7**：配置单每个差异项带来源引用；基准车型为评测集标注的最相似车型 Top1 的比例 ≥ 70%
- **F9**：回答含引用比例 100%；评测集 judge 均分 ≥ 4/5
- **F10**：每次会话可在 Langfuse 看到完整节点级 trace
- **失败路径**：筛选命中 0 时输出冲突约束分析与放宽建议；用户改口（如预算 20 万→15 万）槽位正确覆盖——评测集含无结果 case ≥10、改口 case ≥8
- **结构化输出健壮性**：解析失败自动重试（≤2 次）后降级为追问，成功率 ≥95%

## 5. 非功能需求

- 流式首 token < 2s（国内模型 API 常规网络下）
- 会话可中断恢复：关页重进、评审完成后均能回到正确状态（checkpoint 持久化）
- 成本可观测：单次会话 LLM token 消耗可查（按澄清/检索/生成分阶段统计）
- 数据基线：40 个车型起步（含停售/未覆盖样本），M3 扩至 ≥80；三类知识库各 12 篇起步、M3 扩至各 30
- 公网可访问：M4 部署至 VPS，提供线上演示地址

## 6. 里程碑与验收

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M1 最小闭环（周 1-3） | FastAPI + 手写 function-calling 循环 + SQLite + 40 车型种子 + 筛选/报价/金融纯函数 + 单页 Web 流式聊天 | 端到端演示：选车 → 对比 → 报价 → 金融方案，全程流式 |
| M2 Agent 化（周 4-6） | 迁移 LangGraph 单图 + interrupt（追问/确认）+ 需求单落库（简版）+ 评测集 v1（30 条）+ Langfuse Cloud | 评测集可运行出指标；关页重进会话状态不丢 |
| M3 深度（周 7-9） | 评审挂起/恢复（子图2 或同图多阶段）+ RAG 三类知识库 + vehicle-mcp Server + 成本统计 + 3 轮评估驱动迭代 | 配置单带引用；MCP 工具可被独立客户端调用；每轮迭代的指标变化留痕 |
| M4 收口（周 10-11） | 部署上线（VPS + 迁移 PostgreSQL）+ 极简评审页 + README/架构图/决策日志 | 公网可访问；陌生环境按 README 30 分钟内跑通全流程 |
| 面试冲刺（周 12+） | 八股突击 + LC 加量 + 简历与叙事打磨 | — |

可选扩展（主线完成后再决策）：Android 客户端（约 +2 周）、Next.js 完整管理端、Langfuse 自托管。

## 7. 简历量化口径

- 槽位抽取准确率 / 在售判定准确率 / Top3 推荐命中率：评测集自动统计
- 需求单字段完整率、配置单引用覆盖率：schema 强校验天然 100%，重点讲机制
- 单会话平均成本：Langfuse 统计
- 迭代叙事：三轮评估驱动迭代的前后指标对比（曲线 + 每轮改动说明），比静态数字更有说服力
- 叙事一句话：独立完成端到端智能选车 Agent——Web 用户端 + 极简评审端，LangGraph 编排（中断澄清、异步评审挂起恢复）+ RAG 带引用检索 + MCP 工具层 + 评测与全链路观测。
